How it works

END TO END PIPELINE
1

Discover

A PowerShell generator reads your local Scout automation definitions and per-automation run history. Nothing is hand-maintained, so the dashboard can never drift from reality.

2

Classify

Each automation is matched by keyword against a library of productivity subject areas: calendar hygiene, meeting follow-through, inbox triage, deep work protection, goal tracking, reporting cadence, and more.

3

Score efficiency

Transparent category baselines estimate manual minutes avoided per useful run. Expected monthly savings are compared with successful historical runs to produce realized savings and an efficiency rating.

4

Detect gaps

Subject areas with zero mapped automations become explicit coverage gaps with a recommended addition, so the dashboard tells you what to build next rather than only what exists.

5

Forecast

Recent successful-run velocity predicts next-month savings. Green up means more leverage, yellow right means stable, and down is red unless fewer healthy exception runs indicate reduced intervention demand.

6

Publish safely

A nightly run writes the private OneDrive dashboard, creates a redacted public build, blocks publication if the redaction gate finds sensitive markers, then publishes to GitHub Pages and reports the result in Teams.

Reusable prompt

COPY AND GO

Paste this into a fresh Microsoft Scout session to rebuild this entire system from scratch for anyone. It is written to be portable: no names, no paths, no assumptions about which automations exist.

GOAL
Build me a self-updating "Personal Productivity and Business Execution Command Center":
a single, visually stunning HTML dashboard that tracks every automation I run, groups
them by the area of my life/work they protect, scores their health, and tells me what
is missing. Publish it to my OneDrive and refresh it automatically every night.

DATA SOURCE
Read my local automation definitions and their run history from my agent's automation
store. Do not hand-maintain any list. Everything on the dashboard must be derived from
live data so it can never drift from reality. For each automation capture: name,
description, schedule, enabled/disabled state, last run time, last run status, last
output snippet, and the last several runs for a trend.

CLASSIFICATION MODEL
Do not present automations as a flat list. Classify each one by keyword into the
subject area it actually protects. Use a library like this, and extend it if my
automations suggest a better grouping:
  - Calendar and scheduling hygiene
  - Meeting preparation and follow-up
  - Inbox and communication triage
  - Task and project follow-through
  - Goal and priority tracking
  - Focus time and wellness protection
  - Periodic business review and reporting
  - Relationship and team culture
  - Knowledge capture and documentation
  - Administrative and expense tasks
  - Personal branding and social presence
  - Strategic projects and initiatives
  - System health / meta-monitoring
For every subject area, write one sentence on why it matters to productivity, and one
concrete recommendation for what to add if it is thin.

SCORING
Turn run history into: a health state (healthy / warning / stale / error / running),
a success rate percentage, a human-readable "last run" recency, and a sparkline of
recent runs. Anything failing, stale, or silent must be promoted to a "signals to
review" count at the top, never buried.
Estimate manual time saved per useful run using transparent category baselines. Compare
expected monthly savings with historically realized savings, calculate an efficiency
realization rating, and forecast the next month from recent run velocity. Show a green
up arrow for growth, a yellow right arrow for a stable trend, and a down arrow for
decline. A decline is green only when lower exception-driven activity is beneficial;
otherwise it is red, with a concise explanation.

GAP ANALYSIS
Any subject area with zero mapped automations is an explicit coverage gap. Show gaps
as their own cards with the productivity risk they create and a specific recommended
automation to close them. The dashboard must tell me what to build next, not only what
already exists.

DESIGN - THIS IS THE SHOWCASE PIECE
  - Near-black background, single cool accent color, high contrast, premium and
    futuristic. Treat this as the flagship artifact I demo to other people.
  - Put ME at the center: an animated neural "brain" core rendered on canvas with
    drifting particles, glowing nodes, and proximity-linked synapse lines that shimmer
    and pulse. It should read as 3D and alive, not a static graphic.
  - Surround the brain with KPI stat cards - a three-column stage with stats on the
    left, the brain in the middle, and stats on the right. Never stack everything
    vertically.
  - Clicking the brain expands the functional areas. Lay them out left to right in a
    responsive auto-fill grid at roughly a quarter of the screen width each, so it
    reflows to 4 / 3 / 2 / 1 columns as the browser resizes.
  - Clicking a functional area pops it out: it takes the full row width, lifts toward
    the viewer with a subtle 3D transform and a strong glow, and reveals its
    automations. Only one area open at a time (accordion).
  - Shimmer/sheen must fire only on click as a short one-shot animation. No permanent
    looping shine - that reads cheap.
  - Everything must be one self-contained HTML file. No external assets, no CDN, no
    build step.

TABS
  1. Command center - the brain, KPIs, and the drill-through functional areas.
  2. Recommendations and gaps - automation-to-subject-area mapping with the
     productivity effect of each, plus the coverage gaps and what to add.
  3. How it works and reuse - what the dashboard does, the end-to-end pipeline, and
     this prompt in a copy-to-clipboard block.

AUTOMATION AND NOTIFICATION
  - Write the generator as a script so it can be re-run at any time and is the single
    source of truth for the dashboard.
  - Create a scheduled automation that runs it every night at 8:00 PM.
  - After each refresh, message me in Teams with a short summary: what changed, what
    needs attention, and the top recommended change - then ask whether I want to
    adjust anything.
  - Publish the HTML into a dedicated folder in my OneDrive so it syncs everywhere.

DUAL-BUILD PUBLICATION
  - Generate a private OneDrive build with full automation names and run output.
  - Generate a separate customer-friendly public build with generic category roles,
    no run output, no customer names, and no confidential or personal details.
  - Run a fail-closed redaction gate before publishing the public build. If any
    forbidden marker or run-output block remains, stop and publish nothing.
  - Put a prominent sharing panel and embedded QR code on the private build that links
    to the public URL and clearly labels it non-confidential and publicly accessible.
  - Publish only the redacted build to a static public host such as GitHub Pages.

QUALITY BAR
  - Output must be pure ASCII. Sanitize smart quotes, em dashes, and bullet glyphs
    before writing the file so nothing renders as mojibake.
  - Verify the result in a browser before declaring done: confirm the canvas renders,
    the grid produces the expected column count at a wide viewport, the brain toggle
    works, and expanding an area pops it out and collapses the others.
  - Re-run the generator end to end and confirm it exits clean.
